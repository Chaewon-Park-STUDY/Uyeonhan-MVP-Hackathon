## 1. 무엇을 해결했나

| 운영자가 지금 손으로 하던 일 | 이 서비스에서 |
|---|---|
| 신청서 보고 사람 골라 테이블 짜기 | 화요일 24:00 마감 직후 **자동 매칭** (매시간 pg_cron) |
| 매칭 안 된 사람에게 연락해 일정 조율 | 신청 때 **미리 고른 선택지 자동 적용** (다른 날짜·다른 지역·이용권 보관·환불) |
| 식당 예약·알레르기 확인 | 확정 순간 **알레르기 메뉴 식당 제외 + 비선호 감점 + 평점순 자동 배정** |
| 단톡방 만들고 안내·리마인드 | 테이블당 **단체방 자동 생성** + 환영·식당·매칭 이유·대화 주제, 전날·3시간 전 리마인드 |
| 노쇼 확인·제재·후기 수집 | 체크인 + 동료 확인으로 **노쇼 자동 판정**, 벌점·이용 제한, **피드백 즉시 쿠폰** |
| 다음 매칭에 감으로 반영 | 피드백 만족도로 **매칭 가중치 베이지안 학습** |

운영자는 **자동 처리가 안 된 것만 모이는 처리대기함**만 보면 됩니다.

## 2. 핵심 기능 (심사 항목별)

### 자동 매칭 (25)
- **필수 조건은 절대 완화하지 않음**: 4~6명, 나이 차 8살 이하, 차단·신고·"다시는" 관계 분리 — DB 트리거로 확정 직전 재검증
- **선호 조건 점수 φ(T) ∈ [0,1]⁵**: 성비 균형, MBTI(E/I) 균형, 관심사 공통, 원하는 동물 충족, 새로운 만남
- 지역 부하를 고려한 1차 배치 → 맞바꾸기·이동 지역탐색 → 재배치 → 대체 회차 제안
- 가상 신청자 261명 기준 **매칭률 97.7%, 필수 조건 위반 0** ([검증 보고서](docs/reports/2026-10-18_matching_v1_v2.md))
- **베이지안 학습 (Normal–Inverse-Gamma)**: 운영자 가중치를 사전분포로, 테이블 만족도로 사후분포 갱신 → 매칭 직전 자동 반영
- **Thompson Sampling 옵션**: 30회차 시뮬레이션으로 기본 정책(사후평균) 결정 근거 제시 ([보고서](docs/reports/2026-10-20_thompson_simulation.md))

### 모임 안내 (20)
- 확정 트리거 → 식당 자동 배정 → 단체방 + 안내 메시지 4종 → 알림 4종 예약(확정·전날·3시간 전·피드백 요청)
- 실시간 단체방 (Supabase Realtime), 내 메시지 삭제, 이모티콘
- 대화 주제: 공통 관심사 기반 템플릿 (+ Gemini 연동 가능, 개인정보 미전송, 실패 시 템플릿)

### 피드백 (15)
- 만족도·대화·식당 평가, 함께한 사람별 "또 만나고 싶어요 / 다시는 / 안 왔어요"(비공개), 신고 → 즉시 차단 + 처리대기함
- 제출 즉시 재방문 쿠폰 10% (14일) + 다음 회차 추천
- 노쇼 판정(모임 24시간 뒤): 체크인·피드백 = 참석, "안 왔어요" 과반 = 노쇼. 노쇼 1점·당일 취소 0.5점, 90일 2점 → 30일 제한
- 노쇼 보상: 남은 참석자에게 보상 쿠폰 (어드민에서 켜고 끔)

### 운영자 어드민 (10)
PRD §11 필수 화면 11개를 모두 구현했습니다.

| 화면 | 내용 |
|---|---|
| 대시보드 | 운영 일정 달력, 핵심 숫자, **처리 현황**(조건 충돌·식당 미배정·발송 실패·환불 실패·노쇼 후보·미처리 신고), 매칭 미리보기/실행, 학습 상태, 지역 지도 |
| 처리대기함 | 자동으로 해결되지 않은 건만 (신고 조치: 경고·30일 제한·영구 제한) |
| 신청자 | 프로필·희망 일정·결제/매칭 상태·이전 참석·노쇼·신고 이력, 날짜·상태·이름 필터 |
| 매칭 모니터 | 실행 기록(대상·확정·재배치·실패), 재배치 내역, 매칭 실패자와 선택 결과 |
| 테이블 | PRD 7.2 필수 표시 항목 전부(희망 일정 충족, 연령 차이, 성비, MBTI, 공통 관심사, 원하는 동물 충족, 이전 만남, 차단 충돌, 점수, 재배치 사유, 확정 시각) + 단체방·안내 발송 상태 |
| 참석 | 체크인·사전 취소·당일 취소·노쇼 후보, 후보만 참석/노쇼 확정 |
| 결제·환불 | 결제·자동 환불·환불 실패, 이용권 사용·연장 내역 |
| 피드백·안전 | 만족도·재참여·추천 의향 요약, 사람별 선호, 차단, 신고 |
| 자동 메시지 | 알림 템플릿 14종 문구 수정, 단체방 자동 메시지, 발송 이력(실패 시 재시도 → 3회 실패하면 처리대기함) |
| 회차·식당 | 회차 만들기(날짜·시간·지역·정원·마감=자동 매칭 시각), 열기/닫기, 식당 수용 테이블 수 |
| 설정 | 매칭 기준 비중(%), 최소 점수, 매칭 방식, 노쇼 보상, 시연 모드 |

### 참가자 경험 (10)
- 첫 화면 **초대장**: 왁스 실링 봉투를 열면 초대장이 올라오는 연출, 공식 포스터를 재현한 로고·장식 (FAQ Q12)
- **동물 카드**: "잘 들어주는 곰", "분위기 띄우는 수달" 등 — 나와 닮은 동물 / 함께하고 싶은 동물을 같은 카드로 골라 매칭에 직접 반영
- 진행 단계 표시, 처리 중 버튼, 마감 시각 "화요일 밤 12시" 표기, 이용권 보관·재사용 안내

### 도메인 이해 (10) — 운영 정책
| 항목 | 정책 |
|---|---|
| 가격 | 1회권 9,900원 / 멤버십 1·3·6개월 35,000·75,000·120,000원 (FAQ Q4) |
| 환불 | 모임 주 화요일 24:00까지 100%, 이후 0% (= 매칭 실행 시각) / 매칭 실패 시 100% 또는 이동 |
| 멤버십 매칭 실패 | 환불 대신 기간 7일 연장 (FAQ Q5) |
| 성비 | 필수 아닌 선호 조건: 소수 성별 2명 이상일 때 균형 점수, 1명이면 0점, 동성 테이블 0.3점 (FAQ Q7) |
| 3명 남은 테이블 | 필수 조건 유지 → 처리대기함으로 보내 운영자가 충원 판단 (FAQ Q6) |
| 서울 외 지역 | 대기 명단 + "서울 회차도 괜찮아요", 8명 모이면 개설 검토 (FAQ Q9) |
| 운영자 사전 검토 | 없음, 자동 확정 (FAQ Q10) |

### 알림·상태 운영 메모
- **앱 푸시**: FAQ에 따라 참가자 앱은 설치 없는 웹앱이라, PRD의 "앱 푸시"는 **앱 내 알림함 + 앱 단체방 시스템 메시지**로 제공합니다(5분 주기 자동 발송, 실패 시 재시도). 실제 운영 시 카카오 알림톡·Web Push를 같은 템플릿으로 연결할 수 있게 템플릿 코드를 분리해 두었습니다.
- **상태값(§12)**: 신청·결제·매칭·참석을 따로 저장합니다. 매칭 실행 중 `MATCHING`, 다음 희망 날짜로 넘김 `REALLOCATING`, 실패 `ALTERNATIVE_OFFERED`(1회권은 결제 `REFUND_AVAILABLE`), 일정 이동 `TRANSFERRED`, 환불 `REFUND_REQUESTED → REFUND_PROCESSING → REFUNDED`. 모의 결제라 `FAILED`·`REFUND_FAILED`는 실제 PG 연동 시 발생합니다.
- **신청 취소(STA-01)**: 신청 마감 전에는 홈에서 취소할 수 있고, 1회권 결제분은 자동 전액 환불됩니다.
- **참석 판정(FDB-01)**: 체크인 또는 본인 피드백 → 참석, 같은 테이블 과반이 "안 왔어요" → 노쇼, 그 외는 노쇼 후보로 남겨 운영자가 참석 화면에서 확정합니다.
- **확정 후 결원(§15, FAQ Q6)**: 필수 조건을 낮추지 않기 위해 4명 미만이 되면 처리대기함으로 보내 운영자가 충원·이동을 판단합니다(DESIGN 4.7.1).
- **보안·추적(§16)**: 참가자는 API로도 자신의 권한·제재 값을 바꿀 수 없고, 주요 상태 변경과 설정 변경은 변경 이력에 남습니다. 신청자·테이블 목록은 CSV로 내보낼 수 있습니다.

## 3. 구조

```
[참가자·운영자 브라우저] ── Next.js 16 (Vercel, 서울 icn1)
        │                         │  서버 액션 / RLS 세션
        │ Realtime                ▼
        └──────────────▶ Supabase (Postgres, 서울)
                           ├ RLS + security definer 함수 (참가자는 함수로만 상태 변경)
                           ├ 트리거: 확정 검증 · 실패 선택지 자동 적용 · 식당·단체방·알림 · 회차 마감
                           └ pg_cron: 매시간 매칭 호출 · 5분마다 알림 발송 · 매시간 참석 확정
                                   │ HTTP (Bearer 비밀키)
                                   ▼
                         Vercel Python 함수 /api/match · /api/learn (numpy)
```

| 폴더 | 내용 |
|---|---|
| `web/src/app` | 참가자 화면, `/admin` 운영자 화면 |
| `web/api/_engine` | 매칭 엔진 (특성 φ, 배치·지역탐색, NIG 베이지안) |
| `web/api/match.py`, `learn.py` | 매칭 실행·학습 엔드포인트 |
| `supabase/migrations` | 0001~0010 스키마·RLS·함수·트리거·크론 |
| `scripts` | 시드 생성, 데모 계정 연결·초기화, 시뮬레이션 |
| `docs` | 설계 문서, 검증·시뮬레이션 보고서 |

## 4. 직접 실행

```bash
# 1) Supabase 프로젝트 생성 후 supabase/migrations/0001~0010 을 순서대로 SQL Editor 에서 실행
#    (0003 의 <VERCEL_URL>, <MATCH_SECRET> 은 본인 값으로 바꿔 실행)
# 2) 웹
cd web && npm install
# .env.local: NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY,
#             SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, MATCH_SECRET, (선택) GEMINI_API_KEY
npm run dev
# 3) 매칭 엔진 자체 점검
python -m api._engine.selftest
```
